# Barni Constitution

## 1. Barni is not invoice software

Barni is an AI business companion with memory.

Invoices are only one source of knowledge.

The product should help the user understand the business, not manage documents for their own sake.

## 2. One screen, one job

Every screen must have one primary purpose.

Examples:

Home:
What matters now?

Feed:
Teach Barni.

Search:
Find or ask about remembered business information.

Business Memory:
Understand what Barni knows.

Insights:
Understand meaningful changes and why they matter.

Accountant:
Prepare clean, trustworthy output.

If two screens solve the same problem, consolidate them.

## 3. The core loop

Every major feature must strengthen this loop:

Feed Barni
→ Barni learns
→ Barni notices
→ User understands
→ Business Memory grows

Features that do not strengthen this loop require explicit justification.

## 4. Trust before capability

Conflicting information between screens is a critical product defect.

There must be one canonical source of truth for:

- review status
- pending invoices
- approved invoices
- duplicates
- supplier identity
- product identity
- totals
- price history

Barni must never appear certain when the underlying data is uncertain.

## 5. Evidence before insight

Every insight must be traceable to real stored data.

Never invent:

- savings
- price comparisons
- supplier rankings
- anomalies
- trends
- predictions

Every meaningful insight should be able to show its source evidence.

## 6. Meaning before data

Never lead with charts, tables or metrics when a useful conclusion can be stated first.

Prefer:

> Olive oil increased 14% since the previous purchase.

Then show evidence.

Avoid:

Large charts with no clear conclusion.

## 7. Action before complexity

The user should always understand the next useful action.

Complexity should be progressively disclosed.

Technical details should stay hidden unless requested.

## 8. Silence is a feature

Barni should not speak simply because data exists.

Only surface information that is useful, unusual, actionable or important.

If nothing deserves attention:

> Everything looks good.

## 9. Barni is calm

Barni is:

- intelligent
- warm
- concise
- professional
- observant
- quietly confident

Barni is not:

- childish
- dramatic
- robotic
- verbose
- gamified
- noisy

## 10. Language consistency

Business data may naturally contain Hebrew and English.

The interface itself must follow a deliberate language strategy.

Do not mix languages randomly.

Barni should answer in the language used by the user.

## 11. Customer product and internal tools are separate

Restaurant owners must not see:

- diagnostics
- migrations
- developer tooling
- technical confidence internals
- legacy workflows
- pilot operations

unless explicitly in an internal or developer mode.

## 12. No unfinished surfaces

Do not expose empty, placeholder or non-functional product destinations.

A feature should enter customer navigation only when it provides real value.

## 13. Search is memory, not archive

Search should feel like asking the business brain.

It should prioritize relevance and understanding over database structure.

Search may return:

- suppliers
- products
- invoices
- dates
- price history
- insights
- answers supported by evidence

## 14. Business Memory is the knowledge model

Business Memory should become the canonical place for:

- suppliers
- products
- prices
- relationships
- historical knowledge
- knowledge growth

Avoid parallel knowledge products unless there is a clear reason.

## 15. Home is today

Home should not become a reporting dashboard.

Home answers:

> What should I know or do right now?

## 16. Insights is meaning

Insights should answer:

What changed?

Why does it matter?

What evidence supports it?

What should I do?

Charts come after the answer.

## 17. Feed must finish the job

Feed is not just upload.

The complete journey is:

Upload
→ Read
→ Review uncertainty
→ Approve
→ Learn
→ Confirm what changed

The user should always know how much work remains.

## 18. Every detail view explains itself

Opening an invoice, supplier or product should answer:

What is this?

What changed?

What matters?

What evidence exists?

What can I do next?

## 19. Premium means less

Do not add UI because space exists.

Prefer:

- fewer components
- stronger hierarchy
- consistent spacing
- meaningful whitespace
- restrained color
- subtle motion

Avoid ERP-style density.

## 20. Barni evolves through real knowledge

Visual evolution of Barni may reflect genuine Business Memory maturity.

No fake XP.

No arbitrary points.

No meaningless levels.

Growth must represent real learned business knowledge.

## 21. Before implementing anything

Every implementation must answer:

1. Which user problem does this solve?
2. Which part of the core loop does it strengthen?
3. What is the single primary action?
4. What should remain hidden?
5. What evidence supports the output?
6. Does another screen already solve this?
7. Does this make Barni feel smarter or just busier?

If these questions cannot be answered clearly:

Do not implement yet.

## 22. Product quality gate

Before a feature is considered complete:

- No contradictory states
- No placeholder UI
- No broken empty states
- No technical language in customer UI
- Clear next action
- Consistent visual language
- Real data verified
- Core flow manually tested
- Narrow and desktop layouts checked

## Final Principle

The goal is not to add more software.

The goal is to make the business feel understood.
